## What this commit did

`e2135a17` wired helix_code's "external tier" and helix_agent's
`ExternalSkillSource` through the real `pkg/skills` policy engine
(`RegisterSource -> Load -> Activate`) via a new `PolicyGateExternalTier` /
`LoadExternalTierIntoRegistry` seam in `internal/agent/skill_external_policy.go`,
and routed every production call site (`internal/agent/skill_activation.go`'s
`LoadSkillsAndDispatcher`, `cmd/cli/main.go`'s `buildSubsystems` and the
`skills` CLI dispatcher) through that single seam. Before this fix, neither
consumer's external tier enforced the P4 activation policy (allowlist,
activation ceiling, description-similarity gate, capability-based refusal,
the C5 sandbox precondition) at all — every external-tier skill was admitted
unconditionally.
